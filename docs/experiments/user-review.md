# 실제 사용자 검토 — 2\~3명

3차 피드백: "지인이나 동료가 실제로 짰거나 짜고 있는 서울 일정을 받아 … 처음 입력부터 수정과 재검사까지 걸린
시간과 호출 비용을 남겨주세요. 일정을 바꾸지 않았다면 이미 알고 있던 정보였는지, 지원 장소가 부족했는지, 미확인이
많아 도움이 안 됐는지도 들어보세요."

[블로그 후기 다섯 개 검토](2026-10-19-real-itinerary-review.md)는 남이 이미 다녀온 일정을 우리가 넣어 본 것이다.
이번에는 **일정을 짠 사람이 직접 넣고, 결과를 보고 고친다.** 추가 질문을 이해하는지, 결과를 보고 일정을 바꾸는지는
본인만 답할 수 있다.

## 진행 방법

**누구를** — 서울 일정을 실제로 짰거나 짜고 있는 지인 · 동료 2\~3명. 지원 장소(경복궁 · 창덕궁 · 덕수궁 · 종묘 ·
서울시립미술관 서소문본관)가 하나 이상 들어간 일정이면 된다. 결과가 좋게 나올 일정을 고르지 않는다 — 받은 순서대로 넣는다.

**준비** — 한 사람마다 서버를 새로 켠다(`.venv\Scripts\python core\app.py`, TMAP 키를 넣는다). 서버 창의 `[비용]` 줄이
요청마다 나간 돈을, "서버를 켠 뒤 누적" 이 그 사람 몫 전체를 보여 준다. 시간은 스톱워치로 잰다.

**순서** — 진행하는 사람은 화면을 대신 조작하지 않고 옆에서 본다.

1. 본인이 일정을 자기 말로 적어 넣는다 (스톱워치 시작)
2. 결과를 읽는다. 무엇을 확인했고 무엇을 확인하지 못했는지 본인 말로 설명해 달라고 한다
3. 추가 질문에 답하거나 일정 고치기 표를 고쳐 다시 검사한다. 원하는 만큼 반복한다 (스톱워치 끝)
4. 결과를 보고 실제 일정을 바꿀지 묻는다. 안 바꾼다면 왜인지 묻는다

**개인정보** — 이름 대신 A · B · C로 적는다. 일정 원문은 본인에게 이 문서에 남겨도 되는지 먼저 묻고, 안 된다면 요지만
적는다. 데모 서버는 넣은 일정을 저장하지 않는다(응답 캐시는 평가 실행만 쓴다).
