# 260913 — Google Places · Routes API 능력 확인

**입력 조건** Places API (New) `places:searchText` + Place Details, Routes API `computeRoutes`.
지원 후보 장소 12곳, 이동 구간 3건. 호출 스크립트는 [`check-places-api.mjs`](../../check-places-api.mjs) ·
[`check-routes-api.mjs`](../../check-routes-api.mjs).

> **원본 응답은 이 레포에 저장하지 않는다.** Google Maps Platform 약관상 저장이 허용되는 것은
> `place_id` 와 lat/lng(30일)뿐이다. 근거는 [`docs/data-policy.md`](../data-policy.md).
> 아래는 **API가 무엇을 주는지에 대한 관찰**이고, 응답 값 자체가 아니다.

## 관찰 결과

### Places API — 판정에 필요한 필드가 없다

12곳 전부 `regularOpeningHours` 를 반환했다. 그런데 판정 코어가 요구하는 필드와 맞춰보면 이렇다.

| 판정에 필요한 것 | Places API 제공 | 비고 |
| --- | --- | --- |
| 요일별 운영시간 | ✅ | |
| 정기휴일 | ✅ | 휴무 요일로 표현됨 |
| **입장마감** | ❌ | 개념이 없다. 폐장 시각만 있다 |
| **계절별 시간표** | ❌ | 단일 주간 시간표만 |
| **공휴일 예외 규칙** | ❌ | "정기휴일이 공휴일이면 개방하고 다음 비공휴일로 밀린다" 같은 규칙을 표현할 수 없다 |
| **공휴일 전용 시간표** | ❌ | |
| **적용 기간** | ❌ | 언제까지 유효한 정보인지 알 수 없다 |

12곳 중 공식 정보와 직접 대조한 것은 6곳이고, 정기휴일 요일은 6/6 일치했다.
**운영시간은 불일치가 있었다** — 궁궐 한 곳에서 폐장 시각이 공식 안내와 달랐고,
입장마감은 애초에 필드가 없어 대조 자체가 불가능했다.

### Routes API — 한국에서 모드별 지원이 다르다

| 모드 | 결과 |
| --- | --- |
| `TRANSIT` | 경로 반환 |
| `WALK` | 경로 없음 (HTTP 200, 빈 결과) |
| `DRIVE` | 경로 없음 (HTTP 200, 빈 결과) |

**HTTP 200 인데 결과가 비어 있다.** 이 상태를 "조회했다"로 처리하면 실패가 정상으로 바뀐다.
조회 계층에서 `시간 초과 / 응답 없음 / 필수 필드 누락` 을 구분해야 하는 이유다.

## 해석

- **운영시간의 1차 출처로 Google 을 쓸 수 없다.** 입장마감·계절별·공휴일 예외가 없으면
  검사 4종 중 `ADMISSION_NOT_POSSIBLE` 과 `DWELL_NOT_COMPLETABLE` 을 판정할 근거가 안 된다
- 필드가 채워지는 것과 **필요한 필드가 있는 것**은 다르다. 채움률만 재면 12/12 로 보인다
- 불일치 1건만으로 "보강이 필요한 대상이 국공립 시설뿐"이라고 결론 낼 근거는 없다. 대조 표본이 6곳이다
- 도보 구간을 Routes API 로 해결할 수 없다는 것이 이 시점에 확인됐다

## 결정

- **운영정보는 공식 페이지 curated 로 간다.** Google 은 장소 식별(`place_id`)에만 쓴다
- 원본 응답은 레포에 저장하지 않는다
- 조회 실패를 3종으로 구분하는 것을 조회 계층 요건에 넣는다
