# 260921 — 대중교통 이동시간 조회와 모드 선택

**입력 조건** Routes API `computeRoutes`, `TRANSIT` 모드, 출발 시각 고정, 5구간.
호출 스크립트는 [`fetch-travel-times.mjs`](../../fetch-travel-times.mjs).

> **응답 값(소요시간·거리·steps)은 이 레포에 저장하지 않는다.** 근거는
> [`docs/data-policy.md`](../data-policy.md) — Routes API 약관 §19.3 은 lat/lng 만 30일 허용한다.
> 아래는 관찰과 해석이다.

## 관찰 결과

5구간 전부 `TRANSIT` 으로 경로를 받았다. 한국에서는 `WALK` 모드가 경로를 반환하지 않아
(→ [260913 실험](2026-09-13-google-api-capability.md)) 도보 비교군을 만들 수 없었고,
직선거리 하버사인 근사로 대신 비교했다.

**짧은 구간에서 대중교통 경로가 도보 근사보다 오래 걸리는 사례가 나왔다.**
응답을 보면 도보 이동 → 탑승 → 도보 이동으로 쪼개져 있고, 대기시간이 붙는다.

> 도보로 이동할 수 있는 짧은 구간에도 대중교통 모드로 요청하면 비효율적인 경로가 반환될 수 있으므로,
> **구간별 이동수단 선택이 필요하다.**

이전 메모에 "대중교통이 도보보다 6배 과대평가됐다"고 적어둔 것은 **표현이 틀렸다.**
비교한 두 값은 이동수단이 다르다 — 한쪽은 대중교통 경로, 한쪽은 직선거리 도보 근사다.
이 기록만으로 이동시간 예측이 6배 틀렸다고 결론 낼 수 없다.

## 해석

- 확인된 문제는 "예측이 틀렸다"가 아니라 **"구간에 맞는 이동수단을 고르지 않았다"** 다
- 직선거리 근사에는 실제 보행 경로·출입구·우회가 반영되지 않는다.
  근사값이 여유시간보다 짧다는 이유만으로 통과시킬 수 없다 → `ESTIMATE_ONLY` 로 판정 보류
- **API 응답값과 현장 측정값은 구분해서 표기해야 한다.** 이 실험은 전부 API 응답값이고,
  사람이 실제로 이동해서 측정한 값은 아직 없다

## 결정

- 근사값만 있는 구간은 `unknown` (`unknown_reason: ESTIMATE_ONLY`). 참고 안내로만 쓴다
- 구간별 이동수단 선택을 요건에 넣는다
- **Routes API 응답을 판정용 고정 스냅샷에 넣을 수 없다** (약관). 이동시간 출처를
  공공누리 데이터로 교체한다 — [`docs/data-policy.md`](../data-policy.md) 참조
