# 코드로 따라가기 — N02 시각이 빠진 장소

3차 피드백의 요청은 "고친 반례 하나를 골라 실제 코드를 열고, 입력이 extract → to_itinerary → judge → report → recheck를
거치며 어떻게 바뀌는지 따라가 달라"였다. 새 평가 N02(회귀셋 T34)를 골랐다. 정답을 판정 코드보다 먼저 정했고, 처음 돌렸을 때
검사 칸이 어긋났고, 실패하는 테스트를 먼저 남긴 뒤 고친 사례라서다.

> 11월 17일 화요일이에요. 오전 10시에 덕수궁 들어가서 한 시간 보고, 그다음 창덕궁에서 한 시간 반, 오후 3시 반에 경복궁 들어가서 한 시간 볼게요.

## 1. 기대 결과와 이유를 먼저 정했다

판정 코드를 돌리기 전에 정답을 커밋했다(`be28679`).

- 경복궁은 정기휴일이 화요일이라 이날 쉰다. 휴무일 위반이고, 전체 판정은 **불가능**이다.
- 창덕궁은 정기휴일이 월요일이라 이날 연다. 시각이 없어도 휴무일은 날짜만으로 확인되니 **통과**다.
- 창덕궁에 몇 시에 들어가는지 모르니 입장 · 체류와 창덕궁 앞뒤 이동은 **미확인**이고, 시각을 묻는다.
- 경복궁이 쉬어도 창덕궁 → 경복궁 이동은 해당 없음이 아니라 미확인이다. 휴무일이어도 일부러 갈 수 있다(사용자 결정).

## 2. 처음 돌린 결과 — 판정은 맞고 검사 칸 4개가 달랐다

전체 판정 불가능은 정답과 같았다. 그런데 검사를 하나씩 채점하니 4칸이 달랐다(`a3682d5`, [첫 결과](experiments/2026-10-23-new-eval-first-run.md)).

- 창덕궁은 휴무일 · 입장 · 체류 칸이 아예 없고 "창덕궁에 몇 시에 도착할 예정인가요?" 한 줄뿐이었다. 시각이 빠진 장소는
  검사를 하나도 하지 않았던 것이다.
- 창덕궁 → 경복궁 이동은 경복궁이 쉰다는 이유로 해당 없음이었다.

판정만 맞춰 봤다면 정답으로 지나갔을 문제다. 3차 피드백에서 요청한 검사별 채점으로 찾았다.

## 4. 입력이 코드를 지나며 바뀌는 모습

### extract — 문장을 장소마다 칸으로 옮긴다

[`extract.py`](../core/extract.py#L22)의 `Stop`이 칸을 정한다. Claude는 옮기기만 하고, 판정은 하지 않는다.

| 장소 | start | start_source | dwell_minutes |
| --- | --- | --- | --- |
| 덕수궁 | 10:00 | explicit | 60 |
| 창덕궁 | null | missing | 90 |
| 경복궁 | 15:30 | explicit | 60 |

창덕궁 시각을 "덕수궁이 끝나는 11:00 + 이동시간"으로 채우지 않는다. 추출 규칙 1번이 "입력에 없는 값을 만들지 않는다"이고
([`extract.py:158`](../core/extract.py#L158)), "그다음"은 순서만 말한다. 계산한 시각은 사용자가 말한 시각(explicit)도 아니다.
시각과 출처가 맞지 않으면 형식 검증에서 막힌다([`extract.py:41`](../core/extract.py#L41)).

### to_itinerary — 판정 코어가 읽는 모양으로 바꾼다

[`to_itinerary`](../core/extract.py#L220)는 값을 채우지 않는다. 추출 결과와 사용자가 화면 표에서 고친 일정이 같은 일정 모델
(`Itinerary`)을 지난다(3차 반례 4). 빈 칸은 키째 빠지고([`as_dict`](../core/extract.py#L145)), 창덕궁은
`{"place": "창덕궁", "start_source": "missing", "dwell_minutes": 90, ...}`이 된다.

### judge — 검사하고, 가장 나쁜 상태로 접는다

[`judge`](../core/verdict.py#L932)의 순서다.

1. 날짜나 장소가 아예 없을 때만 판정 전에 묻는다. 장소 하나의 시각이 빠졌다고 멈추지 않는다(3차 반례 2, `b11e840`). 전에는
   여기서 멈춰 "창덕궁에 몇 시에" 한 줄만 남기고 경복궁 휴무 위반을 숨겼다.
2. [`_stop_input`](../core/verdict.py#L112)이 창덕궁 시각이 없다는 입력 검사와 질문을 만든다.
3. [`_untimed_place_checks`](../core/verdict.py#L1098)가 시각이 빠진 장소의 휴무 · 입장 · 체류를 만든다. 휴무일은 날짜로
   확인하고(화요일 창덕궁은 통과), 입장은 시각을 물어 미확인, 체류는 입장을 따라 미확인이다.
4. [`_travel_checks`](../core/verdict.py#L1265)에서 창덕궁 앞뒤 이동은 같은 질문으로 미확인이다. 휴무일인 경복궁으로 가는
   이동도 빼지 않는다.
5. [`verdict_of`](../core/verdict.py#L1370)가 가장 나쁜 상태로 접는다. 위반이 하나라도 있으면 불가능, 없고 미확인이 있으면
   보류, 아니면 가능이다. 미확인이 4개 있어도 경복궁 휴무가 확정이라 **불가능**이다. 창덕궁 시각을 들어도 이 결론은 바뀌지 않는다.

결과는 통과 4(덕수궁 휴무일 · 입장 · 체류, 창덕궁 휴무일) · 미확인 4(창덕궁 입장 · 체류, 앞뒤 이동) · 위반 1(경복궁 휴무일) ·
해당 없음 2(경복궁 입장 · 체류)다.

### report — 결과를 묶고 물을 말을 정한다

- [`questions`](../core/report.py#L151)는 같은 질문을 한 번만 모은다. 미확인 4개가 모두 창덕궁 시각 하나 때문이라 질문은
  "창덕궁에 몇 시에 도착할 예정인가요?" 하나다. 도착 시각만 알면 나서는 시각은 체류 90분을 더해 나온다.
- 경복궁 휴무는 질문이 아니라 안내다 — "이날은 경복궁 휴무일이에요(매주 화요일). 다른 날로 옮기거나 다른 곳을 고르세요.
  입장하지 않고 밖에서만 머물 거라면 그렇게 알려 주세요".
- [`timeline`](../core/report.py#L117)은 장소 · 이동을 일정 순서의 줄로 만들고, 줄마다 가장 나쁜 상태를 보인다.

### recheck — 고친 일정 전체를 다시 판정한다

화면에서 고치면 [`/api/recheck`](../core/app.py#L165)가 [`recheck_revision`](../core/recheck.py#L86)을 부른다. 바뀐 칸만이
아니라 고친 일정 전체를 다시 판정하고, 수정 전 · 후 판정을 같이 돌려준다. 고친 일정도 같은 일정 모델로 검증한다(체류 -60은 422).

| 고친 것 | 다시 판정 |
| --- | --- |
| 창덕궁 11:30이라고 답함 | 불가능 그대로 — 창덕궁 입장 · 체류는 통과로 바뀌지만 경복궁은 여전히 쉰다 |
| 경복궁에 '입장 안 함' 체크(앞에서 쉬다 가기) | 경복궁 휴무 · 입장 · 체류가 해당 없음이 되고, 나머지가 다 되면 가능 |

## 5. 사용자 입력 · 우리 기준 · 외부 근거를 나누는 곳

| | N02에서 | 코드 |
| --- | --- | --- |
| 사용자 입력 | 세 장소의 시각 · 체류, 날짜(연도는 추정, '화요일'은 말함) | `Stop.start_source`가 말한 값 · 추정한 값 · 없는 값을 나눈다. 추정한 값은 `assumptions`에 남기고, 그 값에 기댄 결과는 확정하지 않는다([`_prepare_stop`](../core/verdict.py#L1041) · [`unconfirmed`](../core/verdict.py#L910)). 말한 요일이 날짜와 맞으면 날짜는 확인된 것으로 본다 |
| 우리 기준 | 권장 여유 10분 | [`core/policy.json`](../core/policy.json). 통과를 낼 때만 쓰고, 위반을 가르는 데는 쓰지 않는다 |
| 외부 근거 | 경복궁 정기휴일 화요일, 창덕궁 월요일, 운영시간 | [`core/facts.json`](../core/facts.json) — 공식 페이지 주소 · 확인한 날 · 적용 기간이 붙는다([`check_closed_day`](../core/verdict.py#L202)). 이동시간은 판정할 때 TMAP에서 받고 저장하지 않으며, 받은 출발 시각에만 쓴다([`leg_for`](../core/verdict.py#L505)) |

## 7. 그 뒤 — 시각이 빠진 장소에 들어갈 시간대 (2026-10-25)

N02를 설명하다 나온 사용자 판단이다. 사용자가 장소마다 시각을 정해 두기는 어렵다. 그래서 이동시간을 알면 묻지 않고 들어갈
시간대를 알린다. 앞 장소를 나와 바로 갔을 때(이동시간 + 권장 여유)를 가장 이른 입장으로 보고, 그때 다 되면 통과다
([`_windowed`](../core/verdict.py#L1167)). 시각은 채우지 않고, 이동 0분으로 쳐도 안 되는 검사만 위반이다.

- 같은 일정을 수요일로 하면(T36) 묻지 않고 "창덕궁에는 11:30\~13:35 사이에 들어가면 돼요"를 알리고 가능이다.
- N02 자체는 평가 데이터에 그 구간 이동시간이 없어 지금처럼 시각을 묻는다. 실제로 쓸 때(TMAP)는 앞뒤 구간 이동시간을 받아
  창덕궁을 통과로 보지만, 경복궁 휴무 때문에 여전히 불가능이다.
- 같은 순서로 했다 — 기대 결과를 실패하는 테스트로 먼저(`e18c43f`), 판정 · 화면 · 길찾기를 고치고(`5da2ea6` · `30604e0` ·
  `0efe964`), 회귀셋에 T36 · T37로 넣었다(`73e1bd0`). 테스트는 [`tests/test_time_window.py`](../tests/test_time_window.py)다.
