# itinerary-verifier

여행 일정이 실제로 실행 가능한지 검증한다. **확인한 것 / 어긋난 것 / 확인하지 못한 것**을 근거와 함께 나눠서 낸다.

> Checks whether a travel itinerary is actually executable — validates opening hours,
> closures and transit times against official sources, and **reports what it could not verify**.

## 무엇이 다른가

오류를 못 찾은 것과 문제가 없는 것은 다르다. 이 검증기는 근거를 확보하지 못하면 `pass`를 내지 않는다.

```
verdict = infeasible      확인된 위반이 있다
          undetermined    위반은 없지만 필수 검사가 미확인이다
          feasible        필요한 검사가 모두 통과했다
```

사용자에게도 "실행 가능한 일정입니다"가 아니라 **"확인한 정보와 검사 범위 내에서 위반이 발견되지 않았습니다"**라고 말한다.

## 실행

```bash
pip install anthropic pydantic

# 키 없이 (판정 코어는 외부 API를 부르지 않는다)
python core/run.py                          # 골든 테스트 채점 + 실행 기록
python core/run.py --case T05               # 한 케이스 상세
python core/run.py --all                    # 전부 상세
python core/compare.py --dry-run            # 비교 실험 배선 확인
python core/compare.py --arms code          # 비교 실험, 코드 arm만
python core/build_transit_legs.py           # 지하철 주행시간 하한선 계산

# Anthropic 키 필요
python core/run_extract.py                  # 자연어 → 추출 → 판정
python core/compare.py                      # 비교 실험 4종
python core/compare.py --model claude-sonnet-5
```

키는 실행 시 물어본다. 화면에 안 찍히고 셸 히스토리에도 안 남는다.

### 비교 실험 (claude-opus-5, effort low, 채점 7건)

| 지표 | llm_only | llm_with_facts | code |
| --- | --- | --- | --- |
| 전체 정확도 | 0.286 | 0.857 | **1.0** |
| 오류 표시 중 실제 오류 | – | 1.0 | 1.0 |
| 실제 오류 중 찾아낸 비율 | 0.0 | 1.0 | 1.0 |
| **미확인을 통과로 (건)** | 0 | **1** | **0** |
| 판정 보류 비율 | 1.0 | 0.143 | 0.286 |
| 유효 판단 제공 비율 | 0.0 | **0.857** | 0.714 |
| 건당 비용 | $0.0166 | $0.0688 | **$0** |
| 지연 중앙값 | 8.2초 | 12.1초 | **밀리초** |

누출 1건은 **T08**이다. `"10월 8일 목요일 오후 4시 반에 경복궁 갈게요"` — 체류시간을 말하지 않은 입력인데
LLM은 `feasible`을 냈다. `policy.json`의 `require_user_dwell_for_completion_check: true`를 **문서로 받고도**
적용하지 않고 기본값으로 메워 통과시켰다. 같은 데이터로 코드는 0건이다.

> `llm_only`가 15건 전부 `undetermined`인 것은 발견이 아니다. 시스템 프롬프트에
> "근거 없이 추측하지 말고 unknown으로 둬라"고 **지시했기 때문**이다. 지시를 뺀
> `llm_naive` arm을 추가했고 아직 돌리지 않았다.

## 구조

```
[조회 계층]   외부 API 호출 · 실패 처리
     ↓        fetch_holidays.py · build_transit_legs.py
     ↓        facts.json  (사실)   policy.json  (정책)
[추출]        extract.py — 자연어를 구조로 옮긴다. 값을 채우지 않는다
     ↓        LLM 이 담당하는 유일한 단계
[판정 코어]   verdict.py — 순수 함수. 네트워크 호출 없음
     ↓        checks[] + hard_constraints[] + assumptions[]
[채점·기록]   run.py · run_extract.py · compare.py → last-*.json
```

판정 코어를 외부 API에서 분리했다. **API 없이 고정 입력으로 테스트할 수 있어야** 하기 때문이다.

### LLM과 코드의 경계

| 단계 | 담당 | 이유 |
| --- | --- | --- |
| 자연어 → 구조화 | **LLM** | 표현이 다양해 규칙으로 못 잡는다 |
| 장소 식별 · 운영정보 · 이동시간 조회 | 코드 | |
| **근거 충분성 판단** | **코드** | `unknown`이 여기서 나온다 |
| 실행 가능 여부 판정 | **코드** | LLM은 규칙을 일관되게 적용하지 못했다 (위 T08) |

## 파일별 역할

> 코드 파일 안의 **⭐ 주석**은 그 파일에서 가장 중요한 결정을 표시한 것이다.
> 왜 그렇게 했는지와 그렇게 하지 않으면 무엇이 깨지는지를 적었다.
> JSON은 주석을 달 수 없어 파일 첫 필드에 `_역할` 또는 `note`로 남겼다.

### 판정 — 이 프로젝트의 핵심

| 파일 | 역할 | 세부 설명 |
| --- | --- | --- |
| [`core/verdict.py`](core/verdict.py) | 판정 코어 | **순수 함수.** 일정·사실·정책을 전부 인자로 받고 네트워크를 부르지 않는다. 검사 4종(`CLOSED_DAY`·`ADMISSION_NOT_POSSIBLE`·`DWELL_NOT_COMPLETABLE`·`INSUFFICIENT_TRAVEL_TIME`)을 각각 4상태로 내고, 가장 나쁜 상태를 전체 판정으로 올린다. ⭐ 주석 15개 |

### 입력

| 파일 | 역할 | 세부 설명 |
| --- | --- | --- |
| [`core/extract.py`](core/extract.py) | 자연어 → 구조화 | Claude structured outputs(pydantic). **옮겨 적기만 하고 값을 채우지 않는다** — 없는 값은 `null`로 둔다. 구역만 지목된 입력(`"명동에서 쇼핑"`)은 `scope: area`로 남기고 임의로 점포를 고르지 않는다. ⭐ 주석 3개 |

## 판정 규칙

| 규칙 | 없으면 무엇이 깨지나 |
| --- | --- |
| 근거가 없으면 `unknown` | 확인하지 않은 것을 확인했다고 말한다 |
| 근거의 적용 기간(`valid_until`)이 지나면 못 쓴다 | 작년 시간표로 올해를 판정한다 |
| 입장 가능과 체류 완료는 다른 검사 | 16:30 입장은 되지만 2시간 뒤 폐장인 경우를 통과시킨다 |
| 체류시간을 사용자가 안 말했으면 체류 검사를 안 한다 | 우리가 정한 값으로 사용자 일정의 오류를 만들어낸다 |
| 기본값을 ±50% 흔들어 판정이 뒤집히면 `unknown` | 설정값이 만든 오류를 확정 오류로 보여준다 |
| 근사값으로는 통과시키지 않는다 | 직선거리로 "충분하다"고 하고 실제로는 늦는다 |
| 하한선으로도 늦으면 `fail`, 하한선으로 도착하면 `unknown` | 빠진 값(도보·환승·대기)을 0으로 취급한다 |
| 정보가 부족해도 심각도(`severity`)를 낮추지 않는다 | KTX 문제가 "중요도 낮음"으로 보여 확인을 건너뛴다 |
| 공휴일 시간표가 요일 시간표보다 우선한다 | 한글날(금)에 금요일 시간표를 골라 통과시킨다 |
| `not_applicable`도 근거가 필요하다 | "검사 불필요"를 근거 없이 주장한다 |

## 골든 테스트

라벨은 판정 코드를 보지 않고 공식 페이지 문구에서 만들었다.

| | 케이스 | 잡아내는 것 |
| --- | --- | --- |
| T05 | 대체공휴일 연쇄 | 요일 lookup만 하는 구현 |
| T06 | 기관별 규칙 차이 | 휴무 규칙을 코드에 박는 구현 |
| T08 | 체류시간 미입력 | 기본값으로 메워 판정 ← **LLM이 여기서 누출** |
| T09 | 계절 경계 | 연중 같은 시간으로 처리 |
| T12 | 기본값이 판정을 흔듦 | 설정값으로 확정 오류 생성 |
| T14 | 근거 만료 | 조회 시각만 보고 적용 |
| T15 | 공휴일 시간표 | 요일만 보고 시간표 선택 |

**T05와 T06은 같은 날(2026-10-06)인데 정답이 반대다.** 궁궐은 휴궁, 미술관은 개관. 휴무 규칙을 코드에 박으면 하나는 반드시 틀린다.

| 궁궐 휴무일·관람시간 | 국가유산청 궁능유적본부 | 출처 표시 | 공식 페이지 화면 확인 |
| 미술관 운영시간·휴관 규칙 | 서울시립미술관 관람안내 | 출처 표시 | 공식 페이지 화면 확인 |

Google Places·Routes와 TMAP은 **런타임 조회에는 쓸 수 있지만 스냅샷에는 넣을 수 없다.**
근거는 [`docs/data-policy.md`](docs/data-policy.md).

### 장소 데이터 채움률

**채움률 100%가 목표가 아니다.** 값이 없는 것이 정답인 분류가 있다.

| 분류 | 장소 | 상태 |
| --- | --- | --- |
| 운영시간 검사가 **필요한 시설** | 경복궁·미술관·창덕궁·덕수궁·종묘 | **5/5 확보** |
| 운영시간 개념이 **없을 수 있음** | 청계천·덕수궁 돌담길 | 근거 미확보 → `unknown` |
| **대상 미특정** | 광장시장·북촌한옥마을 | `unknown`이 정답 |

### 아직 검증하지 않은 것

- **도보·환승·대기 이동시간** — 실제 이동시간의 73~85%가 여기다. 지금은 주행시간 하한선만 있다
- 청계천·덕수궁 돌담길의 상시 개방 여부 (공식 근거 미확보)
- 국가유산청·서울시립미술관 페이지의 공공누리 유형
- Google 응답 파생값이 캐싱에 해당하는지 (보수적으로 불가로 처리했다)
- 평가 데이터의 저장·공개 가능 범위 전반

## 남은 작업

| | 왜 |
| --- | --- |
| 라벨 재검토 8건 | 채점이 7건 → 15건으로 늘어난다. 이동시간 케이스(T01·T11·T12)가 전부 빠져 있어 하한선 판정이 비교 실험에서 검증되지 않았다 |
| `llm_naive` arm 실행 | "근거가 없으면 LLM이 추측하는가"를 아직 확인하지 못했다 |
| 도보·환승·대기 데이터 확보 | `undetermined`의 최대 원인 |
| 종묘 회차 입장 검사 | 정보는 확보했고 검사가 없다 (`UNSUPPORTED_ADMISSION_TYPE`) |
| 수정안 생성 + 재검사 | 전체 일정을 다시 검사한 뒤 제시해야 한다. 미착수 |
| 결과를 보지 않은 새 holdout | 현재 15건은 전부 결과를 본 상태다 |
| 테스트 30~50개로 확장 | 표본 7건이라 정밀도·재현율의 신뢰구간이 넓다 |
